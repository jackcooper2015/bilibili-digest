# B 站增强版使用说明

bilibili-digest 基于 [YouTube Digest](https://github.com/zarazhangrui/youtube-digest) 的提交 `bb2f7b1aedb6b50c261c0cf35b0acc7ed631d833` 开发，保留原项目 MIT 许可证和 YouTube 功能。原版仅支持 YouTube，本版本增加 B 站普通视频。

## 安装

1. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择当前项目文件夹，必须直接包含 `manifest.json`。
3. 请将项目保存在长期使用的文件夹中。加载扩展后保持目录位置不变。
4. 刷新已打开的 B 站视频，点击视频下方“视频摘要”，或通过扩展图标打开侧栏。
5. 更新代码后，在扩展管理页点击重新加载，再刷新视频页面。

## 支持范围

- `https://www.bilibili.com/video/BV.../`、`av...` 普通视频页面。
- 分 P 地址中的 `?p=2` 等参数。每个视频和分 P 使用独立缓存及笔记键。
- 分享链接中的追踪参数不参与缓存和导出。短链接需先在浏览器跳转到正式视频页。
- 人工或 B 站自动生成的字幕轨道，优先人工中文，其次自动中文。
- 时间戳字幕、搜索、复制、导出、点击跳转、选中文本保存笔记。
- 使用原项目的 DeepSeek 服务生成章节、金句、解释和翻译；按需调用。
- 视频下方“记笔记”读取当前时间附近字幕并请求 AI 整理，需要 DeepSeek 密钥。选中字幕保存笔记无需 AI。

## 密钥与登录

B 站字幕不经过 Supadata，也不需要 Supadata 密钥。部分字幕只有登录 B 站后才提供，请在同一 Chrome 个人资料中登录，然后刷新视频。扩展不要求复制 Cookie，不读取或保存 Cookie 字符串，字幕请求由视频页携带浏览器正常的站点登录状态发起。

请先等待播放器加载完成。扩展复用播放器已经发出的同视频、同分 P 字幕签名请求；如果提示“尚未发现当前视频的字幕请求”，先等待后重试，仍失败时刷新视频页面。升级后，缺少来源标识的旧版 B 站摘要缓存会自动失效，并重新读取当前视频字幕。

只阅读 B 站字幕无需任何 AI 密钥。需要摘要、解释、翻译或自动整理笔记时，在扩展设置中自行填写 DeepSeek 密钥。密钥保存在扩展本地存储，不要放入代码、聊天或日志。

## 已知限制

- 无字幕轨道的视频、画面内烧录字幕、番剧、直播、付费或受限内容不在本版本支持范围。
- 没有音频下载或语音转写服务；没有字幕时会提示原因，不会用简介冒充视频摘要。
- B 站字幕接口可能变化，平台风控、登录过期和网络故障会影响读取。插件不绕过登录、验证码或访问限制。
- 中文、双语视图沿用原项目“翻译为简体中文”的设计；阅读中文视频通常直接使用原文视图。
- BV 和 av 两种别名分别建立缓存；同一视频建议固定使用 BV 地址。

## 数据流与权限

- B 站视频页请求 `api.bilibili.com` 的视频信息，并复用原生播放器的 `/x/player/wbi/v2` 签名请求读取字幕索引，使用站点正常登录态。请求及响应均校验视频和 CID，签名不写入缓存。
- 字幕文本从允许的 B 站字幕域名获取，不发送 Cookie；拒绝非 HTTPS、未知域名和重定向。
- AI 操作将所需字幕与视频上下文直接发给 DeepSeek。B 站字幕不会发送给 Supadata。
- 缓存、翻译、笔记和密钥保存在当前 Chrome 个人资料；无开发者服务器和遥测。
- 新增的主机权限仅为 `https://www.bilibili.com/*`，用于页面按钮和播放器交互。原项目的 YouTube、Supadata、DeepSeek 权限保持不变。

## 开发验证

```sh
npm test
npm run check
npm run package
```

测试覆盖 URL 规范化、平台和分 P 隔离、CID 选择、字幕解析、登录及无字幕错误、字幕地址校验和页面消息。自动测试不能代替真实浏览器中字幕接口、播放器和 AI 服务的验证。
